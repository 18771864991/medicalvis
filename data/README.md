# Data Files

## Files

| path | description |
| --- | --- |
| `medicalvis_35k.jsonl.gz` | Full MedicalVis-35K corpus |
| `medicalvis_35k_questions.csv` | NLQ-level table with split labels |
| `splits/train.jsonl.gz` | Training split |
| `splits/dev.jsonl.gz` | Development split |
| `splits/test.jsonl.gz` | Test split |
| `schema/` | Public schema metadata |

## JSONL Record Format

```json
{
  "id": "MV00001",
  "vis_query": {
    "DVQ": "Visualize ...",
    "vis_part": "Visualize BAR",
    "data_part": {
      "sql_part": "SELECT ...",
      "binning": ""
    },
    "hardness": "Medium"
  },
  "NLQs": ["Create a bar chart ..."],
  "vis_obj": {
    "chart": "Bar",
    "x_name": "...",
    "y_name": "..."
  },
  "metadata": {
    "chart_type": "Bar",
    "hardness": "Medium",
    "sql_signature_sha1": "..."
  }
}
```

The public release intentionally omits `vis_obj.x_data` and
`vis_obj.y_data`. These fields represent executed query results and must be
generated by running `vis_query.data_part.sql_part` against an authorized local
copy of the underlying clinical database. The repository does not distribute
executed result values for the full dataset. Eight representative HTML
renderings are provided separately under `examples/html/`.

The `metadata.source_split` and `metadata.source_id` fields are provenance
fields from the build process. They are not evaluation split labels. Use the
files under `splits/` for experiments.
